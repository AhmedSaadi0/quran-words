# خطة: ملخص المعنى العام للجذور بالذكاء الاصطناعي

> الهدف: إضافة ملخص عربي مُولَّد بالذكاء الاصطناعي يجمع «المعنى العام» لكل جذر
> من خلال توليف كل التعريفات الواردة في المعاجم الثمانية (`root_meanings`)،
> بحيث يكون حقل واحد جامع لكل الجذر — لا لكل كلمة.

---

## 📊 نقطة البداية (إحصائيات)

| العدد | الوصف |
|-------|-------|
| 1,642 | جذر في جدول `roots` |
| 1,580 | جذر لها تعريفات في `root_meanings` (62 بلا معانٍ — تُتخطى) |
| 9,639 | تعريف من 8 معاجم |
| ~42M | حرف إجمالي (وسيط ~20K حرف/جذر، الأكبر جذر «عرض» بـ269K) |

**المعاجم:** الراغب، ابن سيده، الجوهري، الزمخشري، الخليل، ابن منظور، الزبيدي + معجم عربي-إنجليزي.

## ✍️ دليل أسلوب الملخص (`summary_ar`) — النسخة المعتمدة

1. فصحى واضحة **بتشكيل جزئي وافٍ** للكلمات المهمة والملتبسة، بعناية ودقة في الحركات.
2. **أعمق وأطول:** من 3 إلى 6 جمل (~60–130 كلمة تقريباً؛ وللجذور الضخمة حتى ~150 كلمة).
3. يبدأ بالمعنى الجوهراني المشترك الذي يدور عليه حقل الجذر الدلالي (الأصل اللغوي).
4. يغطي أهم المعاني الحرفية والمجازية، والمشتقات البارزة (الأسماء والصفات وأسماء الله الواردة منه)، مع بيان التدرج الدلالي عند الحاجة.
5. **توليف وتجميع** من جميع المعاجم — وليس نسخ تعريف معجم واحد.
6. بلا ذكر أسماء المعاجم، وبلا شواهد شعرية أو آيات، وبلا تمهيدات («يدل هذا الجذر على…»).

مخطط الـJSON (المفتاح نص الجذر وليس `id` حتى لا تنكسر المراجع عند إعادة البناء):

```json
{
  "نحل": {
    "summary_ar": "العَطاءُ المُجانيُّ ...",
    "model": "muse-spark-1.2-contributor-free",
    "generated_at": "2026-08-25T12:00:00Z"
  },
  "حمد": {
    "summary_ar": null,
    "model": null,
    "generated_at": null
  }
}
```

> **ملاحظة الاستئناف:** الملف يُملأ من البداية بكل الجذور (1,642) — المُنجز يحمل ملخصاً، والمُعلّق يحمل `null`. الموديل يفحص الملف ويبدأ من أول `summary_ar == null` له معانٍ في `root_meanings` (1502 جذر)، والـ62 بلا معانٍ تبقى `null` دائماً.
>
> **ملاحظة الموديل:** الحقل `model` لا يؤخذ نصاً جاهزاً من الخطة؛ الوكيل (الموديل) نفسه يكتب اسمه الدقيق الحالي في كل دفعة (الدفعات القديمة بقيت `ox-alpha`، والدفعات الجديدة تُكتب بـ `muse-spark-1.2-contributor-free`). السكريبتات `merge_summaries.py` و `build_root_ai_summary.py` تحترم ما كتبه الوكيل وتستخدم احتياطاً ديناميكياً (`OPENCODE_MODEL`/`data/current_model.txt` → `muse-spark-1.2-contributor-free`) فقط للدفعات القديمة بصيغة string.

## 🔨 مراحل التنفيذ

### المرحلة 1 — تصدير حزم التعريفات
سكربت `scripts/export_root_bundles.py`:
- يقرأ `root_meanings` ويكتب ملفاً نصياً واحداً لكل جذر في `/tmp/opencode/root_bundles/{root}.txt`
- كل معجم تحت عنوان `##` واضح، والفواصل بينها `---`

```bash
python scripts/export_root_bundles.py                     # كل الجذور
python scripts/export_root_bundles.py --roots "نحل,كتب"   # جذور محددة (تجربة)
```

### المرحلة 2 — التوليد عبر وكلاء متوازنين ← `data/root_ai_summary.json`
- **ملء أولي:** `data/root_ai_summary.json` مُهيأ مسبقاً بكل الجذور (1,642) — 78 مُنجزة و1,564 مُعلّقة (`null`) ليكون الاستئناف التلقائي ممكناً عبر الأيام.
- وكلاء فرعيون، كل وكيل يقرأ حزم جذور (~120–180K حرف لكل وكيل) ويُرجع JSON بالملخصات.
- الجذور العملاقة (روح، عرض…) وكيل مستقل يقرأ الملف على أجزاء ثم يدمج — وهذا هو الـMap-Reduce.
- **ترتيب الأولوية:** الجذور مرتبة تنازلياً بحسب تكرارها في القرآن (من word_morphology) فتُنجز الأهم أولاً (بـ `scripts/build_summary_queue.py`).
- طابور الدفعات في `/tmp/opencode/summary_queue.json` يُبنى من الجذور التي لها `root_meanings` وما زال `summary_ar == null` (حالياً 1,502)، ويُحدَّث تلقائياً بعد كل دمج.
- **الاستئناف:** أي جلسة لاحقة تفحص `root_ai_summary.json` وتبدأ من أول `null` في الطابور — لا حذف للمُنجز.
- الدفعة التجريبية (11 جذراً بينها «نحل») اعتُمدت ثم أُعيد توليدها بالأسلوب النهائي (أعمق + تشكيل).

### المرحلة 3 — التحميل إلى قاعدة البيانات
جدول جديد بإضافة آمنة فقط (بنمط `root_glosses`):

```sql
CREATE TABLE IF NOT EXISTS root_ai_summary (
    root_id      INTEGER PRIMARY KEY REFERENCES roots(id),
    summary_ar   TEXT NOT NULL,
    model        TEXT,
    generated_at TEXT
);
```

سكربت `scripts/build_root_ai_summary.py`: ينشئ الجدول، يحمل فقط الجذور التي لها `summary_ar` غير فارغ من الـJSON، ويطبع تقرير تغطية (الـ `null` لا تُحمّل).

### المرحلة 4 — ربط Backend API
- `backend/roots/models.py`: نموذج `RootAiSummary` (`managed = False`, `db_table = "root_ai_summary"`).
- `backend/roots/serializers.py`: حقل `ai_summary_ar` في `RootSerializer` بنفس نمط `gloss_ar`.
- `backend/roots/views.py`: إرفاق الملخص في الاستعلام.
- اختبار بسيط في `tests.py`.

### المرحلة 5 — التحقق والتوثيق
- مقارنة عينات يدوياً مقابل التعريفات الأصلية.
- تشغيل اختبارات Django + `ruff check`.
- تجربة endpoint الجذور.
- توثيق الجدول والحقل في README.

## ⚠️ مخاطر وملاحظات

- المرحلة 2 الكاملة (1,580 جذر لها معانٍ) تمتد على عدة جلسات/أيام؛ الـJSON مُهيأ بكل الجذور (1,642) مع `null` للمُعلّق وقابل للاستئناف التلقائي بفحص `summary_ar == null`.
- الجذور الـ62 بلا تعريفات تبقى `null` دائماً (حقل فارغ في القاعدة).
- `scripts/merge_summaries.py` يستبدل فقط الـ `null` (لا يلمس المُنجز إلا بـ `--replace`) ويحترم `model` الذي كتبه الوكيل نفسه (احتياط ديناميكي فقط للدفعات القديمة)، و`build_summary_queue.py` يعتبر "مُنجزاً" فقط ما له ملخص غير فارغ.
- `data/root_ai_summary.json` يُضاف ضمن بيانات LFS إن كان حجمه يستوجب.
